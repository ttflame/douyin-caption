# AI 文案改写协作平台需求文档（讨论稿）

版本：0.6  
日期：2026-09-04  
状态：需求讨论中

## 1. 文档目的

本文档用于明确 AI 文案改写协作平台的产品目标、用户角色、核心流程、功能范围和待讨论事项。

当前内容分为三类：

- 已确认：来自当前业务描述，可作为后续设计基础。
- 建议：为保证流程完整而提出，尚需确认。
- 待讨论：不同选择会影响交互方式、数据结构、开发成本或安全方案。

## 2. 产品概述

### 2.1 产品定位

一个供多个成员独立使用的网页版抖音口播稿 AI 改写工作台。成员提交原始文案并完成长度、人设背景、语言风格等创作设置后，系统先分析结构，再提供可独立选择的优化方案；成员确认方案后生成成品，并可锁定成品中的部分内容，通过追加修改要求或局部改写进行多轮迭代，最终形成定稿。

该产品的核心价值不是“让 AI 直接重写”，而是让用户掌握改写决策，并在反复修改中保留满意内容。

### 2.2 产品目标

1. 将文案改写拆成清晰、可控制的步骤。
2. 让用户选择优化策略，而不是被动接受一次生成结果。
3. 支持保留满意片段，降低多轮生成破坏已有成果的概率。
4. 保存完整版本过程，使用户能够比较、回退并最终定稿。
5. 支持多成员使用，且每名成员使用自己的 OpenAI API Key。

### 2.3 非目标（首版建议）

- 不提供成员间共享文案或多人同时编辑同一篇文案。
- 不提供复杂的审批流、绩效统计和组织权限体系。
- 不直接发布到抖音等内容平台。
- 不训练或微调自有模型。
- 不承诺 AI 输出事实完全准确，涉及事实的内容仍需用户确认。

## 3. 用户与角色

### 3.1 成员

已确认能力：

- 使用管理员创建的账号登录。
- 配置和使用自己的 OpenAI API Key。
- 创建、编辑、归档自己的改写任务。
- 完成分析、方案选择、生成、多轮修改和定稿。

### 3.2 管理员（建议）

- 注册、停用或移除成员账号。
- 查看成员状态，但默认不能查看成员的 API Key 明文。
- 新增、编辑、启用、停用平台可选模型，并配置模型名称和实际模型标识。
- 配置基础生成参数范围。
- 查看系统级调用失败和用量概况，但不能查看成员的文案正文、完整提示词和模型响应正文。

### 3.3 权限边界

- 成员之间相互独立，只能查看、修改和调用自己名下的改写任务及模型配置。
- 首版不支持成员间分享、评论、共同修改或转移任务。
- 管理员负责注册和管理账号，但不能查看成员的 API Key 明文。
- 管理员不能查看成员的原始文案、分析结果、优化方案、成品、修改记录及定稿正文，只能查看账号状态和必要的系统运行信息。

## 4. 核心业务对象

### 4.1 改写任务

一次从原文到定稿的完整工作单元。每个任务只生成一篇第一版成品，随后可以围绕该成品进行多轮修改。任务建议包含：

- 任务名称。
- 原始文案。
- 文案用途和发布平台。
- 目标受众、期望风格、字数或时长等创作要求。
- 当前所处阶段。
- 创建者、创建时间、更新时间和定稿时间。

### 4.2 结构分析

AI 根据原文逐条整理文案结构，结果以文本保存。一次重新分析产生一个新分析版本，不覆盖旧结果。

### 4.3 优化方案

基于结构分析生成的一组可独立选择的改写建议。每项建议至少包含：

- 方案名称。
- 发现的问题。
- 建议如何修改。
- 修改理由。
- 预计影响范围或示例。
- 是否被用户采纳。

### 4.4 文案版本

每次生成或二次修改产生一个不可变版本，包含正文、来源版本、使用的优化方案、修改指令、保留片段、模型信息和生成时间。

### 4.5 保留片段

用户从某一成品版本中选中并要求后续版本原样保留的文本。建议记录：

- 片段文本。
- 来源版本。
- 在文案中的顺序。
- 保留强度：必须逐字保留，或允许润色但保持含义。
- 用户备注。

首版只提供“必须逐字保留”，减少语义不确定性。

## 5. 核心业务流程

```text
新建任务
  -> 输入原文并完成创作设置
  -> AI 分析文案结构
  -> 用户查看分析结果
  -> AI 提出多项优化方案
  -> 用户逐项采纳、拒绝或补充要求
  -> AI 生成第一版成品
  -> 用户选择满意片段并标记保留
  -> 用户输入本轮修改要求
  -> AI 生成新版本
  -> 对比、继续修改或回退
  -> 用户确认定稿
```

流程规则：

1. 未确认优化方案前，不自动生成第一版成品。
2. 用户可以不采纳任何建议，并仅使用自己的要求生成。
3. 每次 AI 输出均形成独立记录，不能静默覆盖旧内容。
4. 二次修改默认以用户指定的版本为基础，不一定只能基于最新版本。
5. 标记为“必须逐字保留”的片段，在生成后需要程序自动校验；缺失或改变时必须提示，并允许重新执行失败步骤。
6. 定稿不是流程终点的硬锁定。用户可从定稿版本创建新分支，但原定稿记录保持不变。
7. 每个任务只产生一篇独立的第一版成品；用户需要另一篇独立成品时必须新建任务，不能在原任务中重新生成。
8. 旧任务完整保留，用户可以从任务列表随时返回查看其原文、分析、方案、版本和定稿。

## 6. 功能需求

### 6.1 账号与成员管理

- 支持成员登录、退出和修改密码。
- 成员账号只能由管理员注册，不开放自主注册和邮箱邀请注册。
- 支持管理员停用成员账号。
- 每名成员维护自己的模型连接配置。
- 成员只能使用自己的有效 Key 发起生成任务。

### 6.2 API Key 与模型配置

- 每名成员在自己的“系统设置”页面中维护 API Key 和请求地址。
- 支持录入、更新、验证和删除 OpenAI API Key。
- 支持 OpenAI 官方请求地址和自定义 Base URL。
- Key 输入后仅显示掩码，不提供明文回显。
- 保存前可以发起一次连接测试。
- 清楚显示调用成功、鉴权失败、余额或额度不足、限流、网络异常等状态。
- 调用消耗由对应成员自己的 OpenAI 账户承担。
- 每次任务记录实际使用的模型，但不记录 Key 明文。
- Key 长期保存，成员退出或重新登录后无需再次输入；除非成员主动删除、更新或管理员停用该账号。
- 成员手动填写服务商提供的模型名称，保存到个人连接配置，用于连接测试和 AI 调用；网页端不提供模型管理入口。

保存规则：设置入口位于成员页面，但浏览器不长期保存 Key 明文。Key 提交后由后端按成员加密保存并代理调用；请求地址与该成员的 Key 绑定，任何调用都不得使用其他成员的配置。加密密钥必须通过部署环境配置，不能写入数据库或代码仓库。日志不得记录 Key、请求鉴权头或完整敏感报错。

### 6.3 新建任务与创作设置

- 必填：原始文案。
- 在执行第一次结构分析之前，用户需要先完成或确认创作设置。
- 基础设置建议包括：任务名称、目标字数、目标受众、内容目标、必须包含的信息、禁用表达。
- 文案长度统一按字数设置，不使用口播时长作为长度单位。
- 目标字数支持输入正整数，并提供 300、500、800、1200、2000 字快捷选项。
- 系统提示词按任务规则、人设背景、受众信息、语言风格、内容结构、输出规格、强制约束七部分组合。
- 任务规则由平台内置维护；其余部分由当前任务的创作设置生成，并允许用户使用预设选项后补充自定义内容。
- 人设背景建议包括：账号定位、说话者身份、专业背景、与受众的关系、表达立场。
- 语言风格建议包括：口语化程度、情绪强度、节奏、句子长短、犀利或温和程度、是否使用网络表达。
- 建议补充口播设置：开头方式、叙事方式、行动引导、是否保留停顿或分段、平台敏感表达约束。
- 设置项采用选择器、开关和输入框组合；常用项直接展示，进阶项收纳在折叠区域，避免一次堆叠过多字段。
- 成员可以将创作设置保存为多套个人预设，并在新任务中一键复用、重命名或删除。
- 支持保存草稿。
- 单篇原始文案最多 20,000 字；超出后不允许提交 AI 任务，并提示用户缩减内容。
- 每名成员同一时间最多执行一个 AI 调用，不限制单个任务的累计修改轮数。
- 输入内容超过模型上下文或系统限制时，提前提示，不在调用后才失败。
- 建议自动使用原文前若干字生成任务名称，用户可修改。

### 6.4 结构分析

结构分析只发送提示词“根据原文整理出来一个文案结构，逐条分析”和完整原文。
不附加创作设置、补充说明、固定模块要求或 JSON Schema，模型返回的文本直接保存和展示。
旧任务的七模块分析保留可读，后续优化方案和成品生成支持两种已有结果格式。

操作能力：

- 重新分析。
- 编辑或纠正分析结果。
- 确认分析并进入优化方案阶段。

### 6.5 优化方案选择

- AI 默认一次生成 5～8 条彼此可区分、可独立执行的优化项。
- 优化项分为“优先优化”和“可选优化”两级；优先级由问题对完播、理解和转化的预计影响决定。
- 每项优化建议必须对应结构分析中已经发现的问题，包含问题、修改方向、理由、影响范围和简短示例。
- 用户可逐项选择采纳或不采纳。
- 用户可对单项方案添加备注，例如“接受方向，但语气不要太夸张”。
- 用户可添加自己的优化要求。
- 用户可点击“继续优化方案”：已勾选方案的内容、选择和备注保持不变，仅替换未勾选方案；全部勾选后不可继续优化。
- 确认后形成“本次生成采用的优化清单”。

不提供“方案 A / B / C 三篇完整改写”作为优化选择。首版提供可组合的优化项，例如“压缩开头”“补充冲突”“调整论证顺序”“弱化营销感”，让用户独立勾选。

### 6.6 第一版成品生成

- 使用原文、创作要求、已确认的结构分析和已采纳优化项生成。
- 生成过程中显示明确状态，并支持失败后重试。
- 生成成功后展示成品正文及本次采用的要求。
- 支持复制全文。
- 不提供第一版成品的“重新生成”操作；需要另一篇独立成品时新建任务。
- 第一版生成后，用户通过多轮修改流程产生新版本，不改变该任务只有一个第一版成品的规则。

### 6.7 片段选择与保留

- 成品正文默认按句选择，点击句子标绿保留，再次点击取消保留；编辑模式仍支持选取连续文本保留。
- 保留状态跨生成版本恢复；编辑后的正文在添加保留或再次生成前保存为新版本。
- 已保留文字在正文中显示绿色标识，历史局部保留只标记实际锁定文字。
- 用户可以查看、定位、备注和取消保留片段。
- 重叠选择需要自动合并或阻止，避免产生矛盾约束。
- 后续生成时向 AI 传入全部保留片段，允许按文章结构调整位置和相对顺序。
- 生成完成后由程序逐字校验每个强保留片段。
- 校验失败时，本次结果不保存为版本，任务中心提示失败并提供重试入口；手动编辑也不可改动保留文字，须先取消锁定。

保留规则：片段必须逐字不变，包含标点；重复保留的同一句必须保留足够次数。位置和相对顺序可随文章结构调整。

### 6.8 多轮二次修改

- 用户选择一个历史版本作为修改基础。
- 用户标记需要保留的片段。
- 用户可输入自然语言修改要求，也可直接点击“再次生成”，默认继续优化未保留部分；所有句子均已保留时禁用再次生成。
- 继续优化方案和再次生成均进入后台持久化队列，切换页面不影响执行。
- 系统在生成前展示本轮输入摘要：基础版本、保留片段、修改要求。
- 每轮生成一个新版本，并建立父子关系。
- 支持连续多轮修改，不预设轮数上限；实际受模型额度和系统限制约束。
- 用户可取消生成、失败重试或基于旧版本另开分支。

二次修改支持两种指令范围：

- 全文修改：例如“整体更口语化，控制在 600 字”。
- 局部修改：选择一段后要求“只重写这一段，其他内容不变”。

局部修改纳入首版。用户鼠标选中待修改内容后输入要求，未选中的其他内容默认保持不变；生成后由程序校验未选区域和保留片段，发现非预期变化时明确提示。

### 6.9 版本历史与对比

- 按时间或分支展示所有版本。
- 显示每个版本的来源、修改要求、采用方案和生成时间。
- 支持查看任意版本全文。
- 支持两个版本的差异对比，区分新增、删除和修改。
- 支持从历史版本继续修改。
- 支持给版本添加名称或备注。
- 用户可以直接手动编辑任意成品版本；每次明确保存手工修改时生成一个新版本，不覆盖来源版本。
- 手工编辑期间自动保存编辑草稿，只有用户执行“保存为新版本”后才进入正式版本历史。
- 不允许直接覆盖或删除已作为后续版本基础的版本；可进行归档隐藏。

### 6.10 成品编辑器

- 使用面向抖音口播稿的纯文本编辑器，不提供标题级别、表格、图片、字体、颜色等富文本排版。
- 保留换行和段落结构，支持段落选择、移动、删除和局部改写。
- 支持鼠标选中文字后进行“保留”和“局部修改”。
- 支持撤销、重做、复制全文和实时字数统计。
- 手工输入内容自动保存为编辑草稿，避免刷新或误关闭后丢失。
- 编辑器工具使用统一图标并提供提示，不使用字符代替图标。

### 6.11 定稿与导出

- 用户可以将任意版本设为定稿。
- 一个任务允许保留定稿历史，但标记一个“当前定稿”。
- 支持复制纯文本。
- 支持导出 TXT 和 Markdown。
- 导出内容默认不包含分析过程和提示词；可选导出完整过程记录。

待讨论：是否需要 Word、PDF，以及是否需要直接适配特定平台排版。

### 6.12 任务列表

- 展示任务名称、创建者、当前阶段、当前定稿状态和更新时间。
- 支持按名称搜索。
- 支持按状态、创建者和更新时间筛选（创建者筛选取决于可见性规则）。
- 支持归档和恢复。
- 支持进入任意旧任务并查看完整处理过程。
- 新建任务时可以选择从旧任务复制原文与创作设置，但生成过程和版本相互独立。
- 建议提供自动保存，避免浏览器关闭造成输入丢失。

### 6.13 异常与恢复

- 网络中断、模型限流或浏览器刷新后，不丢失已经保存的原文和历史版本。
- AI 请求失败不得生成空版本。
- 对可重试错误提供重试，对 Key 错误引导成员更新配置。
- 对超时或用户取消的任务记录状态，避免重复扣费的不明确感。
- 若用户重复点击生成，系统应防止同一任务被重复提交。

## 7. 页面与交互结构（建议）

### 7.1 页面清单

1. 登录页。
2. 任务列表页。
3. 文案工作台。
4. API Key 与模型设置页。
5. 成员管理页（管理员）。

### 7.2 文案工作台

建议采用“阶段导航 + 主编辑区 + 上下文侧栏”的结构：

- 阶段导航：原文、结构分析、优化方案、成品修改、定稿。
- 主编辑区：展示当前阶段最重要的内容和操作。
- 上下文侧栏：任务要求、已选方案、保留片段、版本历史，按当前阶段显示必要部分。

交互原则：

- 每个页面只突出当前阶段的一个主要动作。
- 次要设置放入折叠区或弹窗。
- 页面刷新后恢复到上次阶段和编辑状态。
- 长文区域使用预留空间的细滚动条，避免出现时造成布局跳动。
- 所有状态变化使用平滑但短促的动效反馈。
- 图标使用统一图标库，不使用字符代替图标。
- 界面文字不使用粗体，通过字号、颜色和间距建立层级。

### 7.3 建议状态

任务状态：草稿、分析中、待选方案、生成中、修改中、已定稿、已归档。  
AI 调用状态：等待中、执行中、成功、失败、已取消。  
版本校验状态：约束满足、部分保留片段缺失、未校验。

## 8. AI 行为与输出约束

### 8.1 调用拆分

建议将 AI 能力拆分为独立操作：结构分析、优化建议、第一版生成、二次修改。结构分析使用单句提示词和文本输出，优化建议使用结构化输出，生成及修改使用正文输出。

### 8.2 输出要求

- 结构分析返回文本直接展示；优化方案返回可校验的结构化数据，再由前端渲染。
- 成品文案返回纯正文，同时保存模型和生成参数等元数据。
- 系统提示词、用户原文、保留片段和本轮指令必须分层组织，避免互相覆盖。
- 对保留片段使用稳定标识，并在响应后执行确定性文本校验。
- AI 不得宣称已保留片段，最终以程序校验结果为准。
- 保存用户可见结果、创作设置、已选优化项、修改指令、提示词模板版本、模型和生成参数，以支持历史查看和问题追溯。
- 不保存发送给模型供应商的原始请求报文、鉴权头或供应商返回的不可见原始响应；用户可见正文和结构化结果仍按任务保存。

### 8.3 内容安全和隐私

- 明确提示文案会发送给成员所配置的模型服务。
- 禁止在应用日志中记录完整 API Key。
- 是否记录完整提示词和模型响应需要由隐私策略决定。
- 建议提供任务删除能力，并明确删除后数据是否可恢复、备份保留多久。
- 对可能包含个人信息、商业机密的文案给出清晰的数据使用说明。

## 9. 非功能需求

### 9.1 安全

- 全站使用 HTTPS。
- 密码采用成熟的单向哈希算法存储。
- API Key 加密存储，且传输、日志、错误提示中不泄露明文。
- 后端执行成员级权限校验，不能只依赖前端隐藏。
- 防范越权访问、批量尝试登录和跨站请求伪造。

### 9.2 性能与体验

- 普通页面操作应即时反馈。
- AI 长任务显示持续状态，避免用户误判为卡死。
- 长文编辑和版本差异对比在目标文案长度内保持流畅。
- 电脑端支持完整工作流程。
- 手机端提供自适应的任务查看、优化建议选择和定稿确认，不支持复杂选区编辑、段落移动和版本差异操作。

### 9.3 可维护性

- AI 服务、提示词模板、业务流程、用户权限和数据存储分层设计。
- 模型供应商能力通过统一接口隔离，便于后续扩展兼容服务。
- 版本数据不可变，派生关系清晰，避免多轮编辑后状态不可追溯。
- 关键操作和 AI 调用保留审计信息，但不记录密钥明文。

## 10. 首版范围建议

### 10.1 MVP 必须包含

- 管理员创建成员，成员登录。
- 成员在自己的系统设置中配置、验证和更新 API Key 及请求地址。
- 成员在系统设置中手动填写模型名称，无需部署时预置模型列表，网页端不提供模型管理入口。
- 创建和管理自己的改写任务，并返回查看旧任务的完整记录。
- 在分析前配置长度、人设背景、语言风格等创作参数。
- 使用预设与自定义内容配置七部分提示词，并保存多套个人创作预设。
- 结构分析。
- 按原文逐条分析文案结构，以及 5～8 条分级优化方案。
- 根据已选方案生成第一版成品。
- 选择并逐字保留文本片段。
- 使用自然语言进行多轮全文修改和选区局部修改。
- 直接手动编辑成品，并保存为新版本。
- 不可变版本历史、版本查看和基础差异对比。
- 选择版本定稿并复制或导出纯文本。
- 导出 TXT 和 Markdown。
- 自动保存、异常提示和失败重试。

### 10.2 建议后续版本

- 多人共享、评论、审批和实时协作。
- 保留片段的固定位置、固定段落等更精细约束。
- 提示词模板库、品牌语气库和团队术语库。
- 批量处理多篇文案。
- Word、PDF 或平台专用格式导出。
- 用量统计、预算限制和管理员报表。
- 直接发布到内容平台。
- 多模型供应商和自动模型路由。

## 11. MVP 验收标准

1. 成员 A 和成员 B 分别配置自己的 Key，调用与费用互不混用。
2. 管理员和其他成员均无法通过正常产品功能访问某成员的任何文案正文。
3. 成员退出并重新登录后，已保存的 Key 仍可继续使用，但任何页面均不回显其明文。
4. 成员只能选择部署时预置且已启用的模型，不能自行输入模型标识，网页端不提供模型管理入口。
5. 成员能从一段原文完成“分析、选择方案、生成、修改、定稿”的完整流程。
6. 第一次分析前可以自由输入目标字数或选择 300、500、800、1200、2000 字快捷项，并配置人设背景、语言风格等参数；后续 AI 任务准确使用这些设置。
7. 优化方案能够独立选择，生成记录能准确显示本次采用了哪些方案。
8. 任意一次生成都不会覆盖已有版本，用户能回到历史版本继续修改。
9. 用户用鼠标选中文字并点击一次操作即可标记保留；该片段在新版本中会被逐字校验，不满足时界面明确提示。
10. 用户选择局部内容并发出修改要求后，未选区域和已有保留片段不会发生非预期变化。
11. 用户可以直接手动修改成品并保存为新版本，来源版本保持不变。
12. 用户刷新页面或重新登录后，可以继续未完成任务。
13. API Key 不在页面回显、应用日志或普通管理界面中暴露。
14. AI 鉴权失败、限流、超时和网络错误均有可理解的提示及合理恢复入口。
15. 用户能将任意版本设为当前定稿，并导出或复制正文。
16. 成员可以保存、复用、重命名和删除多套个人创作预设，且不能访问其他成员的预设。
17. 超过 20,000 字的原文不能提交 AI 任务；同一成员不能同时启动第二个 AI 任务，但可进行不限轮数的连续修改。
18. 结构分析仅发送指定单句提示词和原文，不附带创作设置或固定模块格式要求；保存并展示返回文本。
19. 每次提供 5～8 条“优先优化”或“可选优化”建议，且每项能追溯到分析中发现的问题。
20. 成品编辑器以纯文本和段落为核心，支持撤销、重做、字数统计、段落操作、保留及局部修改，不出现富文本排版功能。
21. 原任务不存在“重新生成第一版”入口；用户新建任务获得另一篇独立成品，并能随时返回查看旧任务。
22. 系统保存可见结果和必要的追溯元数据，但不保存供应商原始请求报文、鉴权头或不可见原始响应。
23. 用户可以导出 TXT 和 Markdown；手机端可以查看任务、选择建议和确认定稿，但不提供复杂文本编辑。
